Each CR-150 lane has one file named `<lane>.cmake` holding that lane's `list(APPEND TEST_SOURCES ...)` and `pineforge_add_unit_test(...)` lines in the same one-line-per-item form; files are included in sorted name order by the shared include loop at the end of the plain registrations in `tests/CMakeLists.txt`, and a lane must never edit another lane's file.
`set_tests_properties(...)` may name only tests registered by the same lane's file or fence; tests from the main file or another lane are not owned by that lane. Only the property keys `LABELS`, `SKIP_RETURN_CODE`, `RUN_SERIAL`, and `DEPENDS` are allowed (`TIMEOUT` is rejected: this repository declares no time limits, owner rule #827); `set_target_properties(...)` is forbidden. In lane files and fences, `SKIP_RETURN_CODE` must be the literal `77`, the receipt-gated skip sentinel tracked by `scripts/check_abi_receipt_skips.py`; every other skip return code is rejected.

After the include loop, zero or more `# --- CR-150 <lane> begin ---` / `# --- CR-150 <lane> end ---` blocks may appear; each block must be matched, nonnested, unique, and named with the exact stem of an existing `tests/cr150.d/<lane>.cmake` file. The sole unfenced exception is the terminal PR-fast validation block for `PINEFORGE_PR_FAST_TESTS` and its `pineforge_pr_smoke` target. It must remain last: no lane file or fence may follow it.
A fence may register and modify only targets or tests created by that same lane's file or fence, with balanced `if()` / `elseif()` / `else()` / `endif()` blocks; directory or global commands, unknown commands, and writes to other lanes' targets or tests are forbidden.
The only reads of other lanes' targets permitted in a fence are literal `$<TARGET_FILE:x>` expressions and `if(TARGET x)` conditions; plain registrations need no fence, while even a single extra target-definition line such as L19b's must be fenced.
