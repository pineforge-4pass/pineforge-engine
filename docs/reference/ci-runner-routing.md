The merge ruleset requires `pineforge/verify` and `pineforge/parity` commit
statuses on the PR head's exact tree. The maintainers post them from their own (private)
verification tooling after full verification on their x86-64 build hosts and a
parity verdict; an outside contributor cannot post them. GitHub Actions is advisory: `ci.yml` retains PR admission; `gke-pr.yml` runs Release and Debug fast builds, conditional arm64 Debug, preflight and the parity subset. Post-merge `ci-post.yml` runs Release and Debug smoke legs on x86 and arm64, a sanitizer smoke and the parity subset; the full profiles run in the lab's verify (`docs/ci.md`, "Where the full suites run"); there is no macOS cell.
The x86 PR smoke builds in `gke-pr.yml` run the `fast`-labelled CTest rows (`ctest -L '^fast$'`); the post-merge legs (`ci-post.yml`) run
the same `fast` rows on every configuration, and a documentation-only PR runs admission, preflight and the docs build while skipping proof legs.
The seven PR/post-merge verification and documentation workflows start with the canon `authz` job and every other job in them needs it; release uses its status gate and baseline promotion its `promote-guard`. Pull-request
proof workflows and post jobs use exact hosted pins: `ubuntu-24.04` for x86 and `ubuntu-24.04-arm` for the arm64 leg. Promotion, the ruleset probe and docs deployment also run on hosted `ubuntu-24.04`, and keep their `release`/`release-bot` environments. Release's `release`, `prebuilt-x86`, `upload` and `notify-hub` jobs use hosted `ubuntu-24.04`; `prebuilt-arm` retains `ubuntu-22.04-arm`. `release` and `notify-hub` keep their `release` environment. Hosted PR light jobs and `docs.yml`'s `build` retain `ubuntu-24.04`; post guards and aggregates use the same pin.
Hosted fork PRs receive no secrets, so they need no VM-only fork-refusal hook. Retired main/post VM labels remain refused. The retired `gke-*` scale sets and paid larger-runner labels are refused too. Group 14's mirror `.github/runner-group-allowlist.txt` and group 15's mirror `.github/runner-group-15-allowlist.txt` are empty for the current hosted workflows. The exact prior isolated and hosted-matrix release forms remain admitted for rollback; restoring a protected route requires its mirror entry and live group membership.
Release's `prebuilt-x86` alone receives OIDC permission for the pinned auth action and dedicated private-toolchain reader on dispatch from main with the exact `release.yml` identity. Both builds assert Eigen 3.4.0 and check every staged library against the v1.10.0 baseline; x86 consumes its packed archive before artifact handoff. `upload` has release-write permission without OIDC and re-hashes both downloads against build outputs before publication; `notify-hub` follows it. The same-repository non-fork PR diagnostic checks out the exact head without persisted credentials and records host identity, Docker versions and storage driver without auth, pull, build or tests. App-token jobs keep their exact `release`/`release-bot` environments. The `build-gate` job in `ci-post.yml` and `native-live.yml`'s `native-live-gate` always run and refuse a non-success authz result first.
