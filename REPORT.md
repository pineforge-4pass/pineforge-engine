## 2. Code versus design

The design coordinates are those of d0bece7ae9; this tree is 6cfcff0696, which differs only in tests, and every declaration cited here was re-read in this worktree. Formulas follow ../../core-cr150-o1roots/wt/REPORT.md exactly: cohort :116, e :135, c :145-147, rank :159, root and alias capacity :82. Differences, each deliberate:

1. c reports the EXACT distinct joined-key count and bytes rather than the closed-form upper bound. The two agree when no component contains 0x1f and are never larger otherwise, which is the "joined-key dedup" the brief names (../../core-cr150-o1roots/wt/REPORT.md:147).
2. The design says the public v1 `R` means ALL rooted successors and must not be relabelled "live roots" (../../core-cr150-o1roots/wt/REPORT.md:112; include/pineforge/pineforge.h:841-857). The code therefore keeps the new root and alias counts outside `ScratchManifest` and leaves `R` at 0 (include/pineforge/detail/scratch_facts.hpp:254-258). No public ABI addition is proposed or needed.
3. The design leaves the begin protocol and the certificate transport open (../../core-cr150-o1roots/wt/REPORT.md:36-38). The wire format is therefore new design work of this lane, bounded by brief item 1d.
